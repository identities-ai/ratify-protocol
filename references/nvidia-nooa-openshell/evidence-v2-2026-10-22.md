# NVIDIA NOOA + OpenShell reference: Protocol v2 evidence (2026-10-22)

This record covers the reference after its port to Ratify Protocol v2. The
Protocol v1 record (181 tests; live OpenShell v0.0.102 profile at 64/64 gates
against the published `ratify-protocol==1.0.0a20` on 2026-09-18; the earlier
v0.0.96 campaign) is unchanged and kept as dated history in
[`docs/evidence/nvidia-reference-evidence.md`](../../docs/evidence/nvidia-reference-evidence.md).

**Status: pre-release.** Both runs below used the v2 SDK built from this
repository checkout (`ratify-protocol-v2` and `ratify-protocol-native-v2`
`2.0.0a1`), not published packages. They must be repeated against the
published `2.0.0-beta.1` packages (`RATIFY_SDK=published`, after resolving the
`TODO(RATIFY_V2_PIN)` markers) before this reference is described as tested on
a released v2. The receiver's claim store, receipt log, checkpoint, journal and
challenge issuance store are the SDK's in-memory reference stores: development
only. Review of Protocol v2 so far is internal; external review is a gate for
`2.0.0`.

What changed in the case expectations for v2, and why:

- `revocation_provider_failure` is now a committed, receipted
  `authorization_unverified` (`status_unavailable`) decision rather than v1's
  `invalid`: an unreachable signed-status feed fails closed after the claim.
- `chain_above_protocol_maximum` (nine certificates) is refused at the MCP
  boundary as a malformed proof, because the v2 codec does not decode a chain
  above depth 8. In v1 the verifier refused it and wrote a receipt.
- `wrong_agent_key`, `cross_request_proof_movement` and `invalid_challenge`
  remain unsigned refusals; under v2 they fail preflight
  (`chain_linkage_mismatch`, `challenge_mismatch`,
  `expected_challenge_unavailable`) before any claim.
- The `sandbox_clock_within_presenter_safety_margin` gate is retained as a
  clock-discipline diagnostic so the gate set stays comparable with v1. Under
  v2 the presentation's `challenge_at` is the receiver's issuance time, so no
  protocol check reads the sandbox clock.
